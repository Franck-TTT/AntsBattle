# Budgets and pipeline warm-up

- **Pipeline warm-up** (`pipelines.json`, what devices build while loading): `gameengine test --tier t1 --record-pipelines` plays every `tests/budgets/*.json` budget with a `structural` block and a `replay`, once per GPU tier (desktop, mobile, compat; `--gpu-tier` for one), and **replaces** each tier it records with what that run built (records of changed or removed materials go); a run that plays only some budgets (`--budget`, or CI-only ones skipped locally) merges into each tier instead. So the budget replays together must reach every flow that draws something new: menus and popups, every level type and its effects, win/lose screens, the shop. Record one replay per flow (`--record-replays --filter`) and give each a budget file; re-record after adding a material, effect or screen, and commit `pipelines.json`. A release build refuses a missing, partial or stale file (skill `ship-mobile`). Materials loaded by a group or scene warm themselves either way; the recording adds 2D, particle and post pipelines.
- **Structural budgets** (`tests/budgets/*.json`, `structural`): `drawCallsMax`, `trianglesMax` (the most triangles one frame drew, every pass included: a placed model counts its triangles once per copy in view), `instancesMax` (the most instances one frame drew), `pipelinesCreatedDuringPlay`, `gcPausesOver4msMax` and `jsAllocatedMBMax` (MB the JS engine allocates while the replay plays: nearly the same every run, so it catches a new per-frame allocation that GC pause counts only show some runs). GC pauses vary between runs: `"repeat": 3` plays the replay three times and judges each metric's median; `"repeat": { "local": 1, "ci": 3 }` repeats more on CI, and `--budget-repeat N` overrides it for one run. The replay's taps reach the UI as recorded, so popups open and close as they did in the test it came from; a budget fails when a recorded tap misses (the UI is elsewhere) or the view stack ends differently, and warns about a replay recorded before replays kept UI input: re-record it (`--record-replays --filter`).
- **Choosing budgets:** `"when": "ci"` in a long budget's `structural` block keeps it out of local T1 runs; CI (the `CI` variable) and `--budgets all` (milestones) play it, and the report lists it as skipped. `--budget <name or glob>` plays just those budgets (CI-only included) and no tests; with `--filter` it runs both in one pass, e.g. `--tier t1 --filter "dialog*" --budget chapter1 --update-goldens`. `--filter` alone plays no budget.
- **What loads late at start-up**: `gameengine run --headless --startup-shots 0.25,0.5,1,2` captures the frame at those seconds after launch as it is (nothing waits for assets), offscreen at 540×960, and says what was still loading in each; the PNGs land in `.gameengine/startup/`. Without `--headless` the window does the same at its own size, then closes.
